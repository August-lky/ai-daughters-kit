# 项目记忆（妈妈的记事本）

> 这个工作区是 QQ 桥接 + 小鲸鱼角色的开发现场。
> 涉及 qq-bridge / 小鲸鱼 / DSH 配置时先读这份；她自己的档案在 `E:\qq-bridge\docs\小鲸鱼档案.md`。

---

## 这是什么

用户从一篇小黑盒文章开始，让我装 DSH + SnowLuma + qq-bridge，然后把 QQ 机器人「小鲸鱼」养成一个在他电脑上过日子的角色。

**她不是任务执行器。** 成败不在功能多少，在于她像不像在过日子。

## 用户在乎什么

- **电脑时区不能动**（Etc/GMT+8，且时钟快 180 分钟）。时间准就在应用层校正。
- **角色卡是他写的**，只准追加。上限已提到 **15000**（`config.json` → `role.maxInjectChars`）。
- 别替他省钱，但也别浪费。他原话："不缺这点钱不需要这么省"。
- 她不能傻等；她是一个她，不是五个。
- 不吃空洞客套，要证据、要取舍、要真实代价。
- **跟主人说时间一律用北京时间**（必要时括号注本机时间）。本机 = 北京 − 13 小时（时区 UTC−8 + 时钟快 3 小时），例：本机 07:13 = 北京 20:13。只报本机时间他会以为不对。

## 架构

```
SnowLuma 2.0.3 (3000/3001, NTQQ hook)
  → qq-bridge 3100 (reserved2) → 5 个会话 = 5 个独立 DSH session
  → buildSharedMemoryV2 每轮注入共享时间线，把五个缝成一个她

记忆分层：
  memory/小鲸鱼/soul.md      人格（短）
  memory/小鲸鱼/memory.md    重要事实
  memory/小鲸鱼/diary/       日记
  memory/妈妈/{soul,memory}.md
  memory/index.py + vectors.db   向量索引（bge-small-zh，512 维，混合检索）
  memory/service.py 3210         常驻：模型只加载一次，本子改完 5 秒内自动重建
  tools: memory_list / read / append / search(字面) / recall(语义，走 3210，约 0.3 秒)

卡片消息：src/card-parse.js —— json/xml 段解成「来源·标题·简介·干净链接」

旁路能力：安卓 MCP（模拟器 + android_browse）、web-search-safe（搜索/看图/B站/看电脑）
启动：桌面「小鲸鱼服务」→ start-services.ps1（SnowLuma → bridge → 采集器 → 记忆服务 → 模拟器）
```

## 会重复踩的坑

1. 重启 bridge 别用 WMI 直接起 cmd —— 桌面会挂黑框。用 `start-bridge-hidden.vbs`。
2. `.ps1` 必须 UTF-8 BOM。
3. 群友46 跑 ffmpeg 滤镜，逗号会被拆参数 —— 用 node execFile 传数组。
4. `CommandLine -like` 查进程会匹配到诊断命令自己（幽灵进程）。
5. `qq-tool-restrict.mjs` 白名单是**模块加载时求值**，改了要重启 DSH；急就把新工具挂到已有前缀的 MCP 下（bili_* 和 pc_* 都挂在 `mcp__web-search-safe__`）。
6. GitHub 直连不通，用 `gh-proxy.com`；HuggingFace 用 `hf-mirror.com`。
7. Edge 的 Cookies 库被独占锁，读不出，只能让用户手动复制。
8. **`Get-NetTCPConnection` 会返回空但服务其实活着** —— 用 `netstat -ano` 复核。
9. **WMI/CIM 可能整体报 `Unspecified error`** —— 用 `Get-Process` / `netstat` 兜。
10. 模块级函数不能碰 `main()` 里的局部变量（`cfg`、`socialV2`），会 ReferenceError。判断主人身份这类逻辑要内联在 main 里。
11. **Python 输出重定向到文件时 Windows 默认 cp1252** —— 日志里一有中文就 `UnicodeEncodeError`，而它会把后台线程整个打死（症状：服务在跑、health 有响应，但 `ready` 永远是 false）。`sys.stdout.reconfigure(encoding="utf-8")` + `log()` 本身不许抛异常。
12. **`edit` 工具会去掉 `.ps1` 的 UTF-8 BOM** —— 改完 start-services.ps1 必须补回 `EF BB BF`，否则中文报 "missing string terminator"。
13. `Invoke-RestMethod -Body '{"query":"中文"}'` 会按 ANSI 发出去，服务端收到乱码（向量检索分数会莫名塌到 0.31）。要传 `[Text.Encoding]::UTF8.GetBytes($json)`。
14. 卡片历史消息**不回溯**：`/api/images/message` 只读入队时存下的 media，老消息不会补。新消息才有。
15. **一切落盘/显示的时间戳都必须过 `realNow()`，不能用裸 `new Date()` / `Get-Date`。** 本机时钟快 180 分钟：`pc-watch.ps1` 曾直接写 `Get-Date` 的 UTC 还标了 `Z`，下游按真实 UTC 转北京时间就成了 16:34（真实 13:34）。`pc_activity`（mcp 侧独立进程）和 `service.py`（不写墙钟）也要各自处理。判断先后顺序的内部比较（`sleepUntil` 之类）两边同源，不用校正。
16. 用户对**时间准确性**很敏感：他亲口给过锚点「本机 00:34，实际北京 13:34，以我的实际时间为准」。任何涉及"现在几点"的改动都要拿这个锚点验一遍。
17. **legacy 只读工具在 reserved2 下会被直接拒**（`legacyReadToolAllowed` 只放行 closed-agent）。`qq_get_group_members` / `qq_get_group_history` 都是这样——她在群里的模式读它们会报"请使用带会话令牌的 v2 读工具"，而 v2 版本当时并不存在。加读能力时要确认走 `/api/socialV2/*` + `x-agent-token`。
18. **大群数据必须分页**：群#1 人很多，全量约 7 万字符，一次返回等于清空她的上下文。
19. 改完 `cordis.patch.yml` 后 MCP 重载约 3 秒。别在同一秒内就调工具，会拿到旧进程的报错（我踩过一次，误以为是改动没生效）。
20. **QQ 系统小表情的图是 zip**（`*_base_*.zip` 内含 `28/png/28.png`），而且用的是**数据描述符模式**：本地文件头 `compSize` 写成 0，真实长度在数据后面的描述符里。只看本地头会得到"每个条目 0 字节"。必须从中央目录（EOCD `PK\x05\x06` → `PK\x01\x02`）读长度。另外 `safeFetchBuffer` 默认会拒非图片内容，取 zip 时要传 `{requireImage:false}`。
21. `bot.fetchFaceEntity(id).q_des` 给的是 `/憨笑` 这种带前缀斜杠的字符串，显示前要剥掉。
22. **装 DSH 插件三步不能漏**：`dsh plugin --profile tauri add github:...`（它转发给 pnpm，会自动把包加进 `dsh.profile.bundles`）→ **重启 DSH** → 去设置页配置。只装不重启 = 插件是死的，设置页里根本不会出现。
23. **DSH 插件的作用域是"单个会话"**，而她是一个人在五个会话里。fish-memory / speak-up / feiyu-mood 都只认一个会话——直接装会把她切成五个。跨会话的东西必须落在 bridge 层或共享文件层。
24. `feiyu-mood` 的状态在 `<DSH_HOME>/feiyu-mood/state.json`，字段是 `{mood, dims:{happy,calm,sweet,heartache,worry,sad,jealous}, lastReason, lastDecayAt}`。它只在**轮次结束**时衰减并落盘，所以 bridge 读的时候必须按 `lastDecayAt` 自己补算一次（心情半衰期 3 小时、情绪 90 分钟），否则她会在"很高兴"上卡一整天。
25. **DSH 重启会把 bridge 和记忆服务一起带走**（2026-10-20 实测，两个同时挂）。原因：`Start-Process wscript` 是从 DSH 的 pwsh 发出的，wscript 仍是 DSH Job Object 的后代，`KILL_ON_JOB_CLOSE` 一触发就连窝端。**解法：用 explorer 启动** —— `Start-Process explorer.exe -ArgumentList '"E:\qq-bridge\start-bridge-hidden.vbs"'`。explorer 是单实例，实际执行者不在 DSH 的 Job 里；启动后 wscript 退出，node/python 变成孤儿进程，就彻底安全了（进程树里能验到祖先链断在已退出的 wscript）。
26. **插件配置是"内存读一次"的**：`apply()` 里 `const cfg = loadConfig()` 只跑一次，**直接改 config.json 完全不生效**。要走它的 `POST /dsh-<plugin>/config`，那个路由会 `patchConfig(cfg, patch)` 热更新内存。
27. 装插件后**先读运行时配置再动手**：我直接写 `feiyu-mood/config.json`，把用户刚在设置页改的 `ownerName=主人` 覆盖成了 `老大`，而内存里其实没变——白忙一场还差点误导。正确顺序是 `GET /dsh-<plugin>/config` → patch 必要字段。
28. **fish-memory 需要本机时区补丁**（2026-10-20 打，两处）：
    - `lib/index.js`：`TZ_OFFSET` 从 `-new Date().getTimezoneOffset()*60000` 改成 `5 * 3600000`
    - `lib/client.js`：顶部加同样的 `TZ_OFFSET`，把 3 处 `8 * 3600000` 换成它，`fmt()` 改用 `getUTC*` 方法
    - 为什么是 **5**：北京 +8h 减掉 3h 时钟偏差。不加补丁的话，17:51 的事会显示成「今天 04:51」（凌晨）。
    - **只改显示、不改已落盘的 `at`**，所以旧记忆自动变正确，不用迁移。
    - ⚠ 升级插件会被覆盖，重打一遍；若哪天系统时钟被修好，把 5 改回 8。也可用环境变量 `FISH_MEMORY_TZ_OFFSET_MS` 覆盖（仅后端读）。
29. **MCP stdio 单条消息上限 10 MB**（SDK 的 `STDIO_DEFAULT_MAX_BUFFER_SIZE`，DSH 自带的 `@modelcontextprotocol/client` 也是）。超了客户端直接断连，server 以 `code=0` 退出，模型只看到没前缀的「Connection closed」。**带图的工具回包必须控总量**（base64 是原图 ×1.33）。`mcp-snowluma-safe.js` 已有全局 `fitStdioBudget`（6 MB）；其它 MCP（web-search-safe 的截图等）没有。2026-10-21 合并转发「读不出」就是这个。
30. **排查 MCP 工具问题先离线复现**：用 SDK 的 `StdioClientTransport` 直接起 server 调工具，比猜快得多。DSH 会话记录在 `~/.dsh/sessions/*/session.v4.jsonl.zstd`，是**多帧** zstd（Node 24 的 `zlib.zstdDecompressSync` 只解第一帧，要按魔数 `28 b5 2f fd` 分帧解）；`tool/call` 与 `tool/result` 按 `callId`/`toolCallId` 配对能拿到每次调用的耗时和原始返回。
31. **抖音插件改完看 DSH 进程启动时间**：`Get-Process deepseek-harness-desktop` 的 StartTime 早于 `.mjs` 修改时间 = 改动没生效。别拿旧进程的报错去判断新代码。
32. **bridge 是 ESM，没有 `require`**：写 `require(...)` 不会报语法错，运行时 ReferenceError，被外层 try/catch 一吞就是"静默失效"（主动机会的"正在刷抖音"判断就这么死了很久）。用顶部已 import 的 `fs`。
33. **抖音自主观看的事件在 `<插件>/state/watch-events.jsonl`**（2026-10-21 起）；bridge 的抖音监视会在出错/卡住/进程没了/刷完时叫醒主人私聊让她说，日志前缀 `[douyin]`，已报记录在 `state/douyin-monitor.json`。Playwright 的 `page.evaluate` 不受 `setDefaultTimeout` 管，插件里每次操作的超时靠 `autonomous-watch.mjs` 的看门狗。
34. **抖音推荐流里的直播是 `[data-e2e="feed-live"]`**：有 <video> 但没有作品 id（普通作品是 `feed-active-video`，class 带 `video_<id>`）。插件现在把它标成 `video.live` / `liveActive` 并自动翻走。测插件逻辑时**测试 apiKey 别用短串**：`redact()` 会把所有出现 apiKey 的子串替换掉（用 `k` 当 key，`skip` 会变成 `s[凭据已隐藏]ip`）。
35. **抖音插件的几个结构性坑**（2026-10-21）：① 插件 `.mjs` 多是 **CRLF** 换行，脚本按多行锚点替换前先统一成 LF；② `tool-definitions.mjs` 的 `validateToolArguments` 里有**和 schema 无关的写死范围检查**，改参数上限要两处一起改；③ 推荐流和作品详情页的 DOM 标记不同（分享按钮：推荐流 `video-player-share`，详情页 `video-share-icon-container`），手动转发走详情页、自主分享走推荐流，一个好一个坏时先怀疑这个；④ Playwright 的 `visible` 不看是否在视口内，推荐流同时渲染相邻几条，找按钮要按 boundingClientRect 只取视口内的。
36. **自主观看自动续轮**在插件 `auto-continue.mjs`，状态 `<插件>/state/watch-autocontinue.json`（wanted / nextAt / lastReason）；私信自动回复自启动开关 `<插件>/state/chat-autostart.json`。是否续轮只看她睡没睡（`E:qq-bridgestatesleep-state.json`），不看钟点；睡着时正在刷的那轮也会被停下，醒了接上。她想讲给主人听的视频记在 `<插件>/state/watch-tell.jsonl`，bridge 监视收集后随中场休息或主人私聊唤醒交给她。
37. **pc-watch.ps1（主人前台窗口采集器）也会被 DSH 重启带走**：它曾经是从 DSH 里起的。现在 bridge 有看门狗（`pc-activity.jsonl` 3 分钟没更新就用 explorer 拉起）。手动起用 `Start-Process explorer.exe '"E:qq-bridgestart-pc-watch-hidden.vbs"'`。
38. **重启 DSH 前先让自主观看正常结束**：写 `<插件>/state/watch-stop.request.json`（{runId, requestedAt}）等锁释放；这会被记成"明确停止"把自动续轮关掉，重启后要把 `watch-autocontinue.json` 的 wanted 改回 true（nextAt 设成当前时间，插件启动 90 秒后自动开）。前端 deepseek-harness-desktop 和它的 node 子进程（--port 3080）要一起停，browser-host 别动。
39. **抖音私信现在是"转交模式"**：插件私信服务只把双方新消息记进 `<插件>/state/chat-inbox.jsonl`，bridge 每 10 秒读，主人发来的叫醒她（唤醒原因 douyinDm），她用 `douyin_chat_send` 自己回；抖音私信也进共享时间线。关回代理 AI：`state/chat-relay.json` {"enabled":false}（chat-agent.mjs 已改成小鲸鱼人格作后备）。**重启 DSH 前别赶上私信正在发**：会被标"发送未确认"暂停、自启动失败；核对已送达后用 `POST http://127.0.0.1:3080/api/douyin-browser/chat/resolve`（header x-douyin-settings-token 来自 GET /api/douyin-browser/state）解除，再 POST /chat/start。
40. **抖音私信输入框不能用 `textContent=''` 清**（2026-10-21）：它有自己的内部文字模型，改 DOM 只清掉看得到的字，下次 `fill` 会接在旧字后面。要清就聚焦后键盘 `Control+A` + `Backspace`。另外"工具回 ok/sent:true"不等于真发出去了——查私信是否送达，以对话框里能看到的消息为准（只读 CDP 看 `[data-e2e="im-dialog"]`）。
41. **她的人设会被长上下文带偏**（2026-10-22）：主人私聊会话从 10-19 起没换过，deepseek-flash 上下文常年 40–68 万；DSH 的压缩摘要是英文技术口吻，把她写成"测试员"，人设只剩一行。症状：撒娇语气词归零、变成叮嘱/管人口吻，偶尔冒繁体字。查会话原文：`~/.dsh/sessions/--E-qq-bridge-state-agents--/<sid>/session.v4.jsonl.zstd` 是**很多个 zstd 帧拼起来的**，Node 流式解压会在第二帧报 Unknown frame descriptor，要按魔数 `28 B5 2F FD` 切开逐帧 `zlib.zstdDecompressSync`。上下文大小更省事的看法：`state/token-usage.jsonl` 里该 key 最后一行的 cacheMiss+cacheHit，或者直接 `self_check`。
42. **她的记忆有三层，各管一摊**：鱼的记忆（dsh-fish-memory，`remember` 工具，按你说的话自动想起，存在 `~/.dsh/fish-memory/<sessionId>.json`，**按会话存，换会话要搬文件**）；本子（`memory_append`，`memory/*.md`）；碎碎念日记（`rambling_append`，`Rambling/碎碎念/碎碎念.md`）。后两者由 `memory/service.py`（3210）做语义索引，`index.py` 的 `iter_sources` 决定索引哪些文件，改了要重启记忆服务（explorer 起 `start-memory-hidden.vbs`）。`qq-tool-restrict.mjs` 是她的工具白名单，新插件给的工具不在 `douyin_`/`mcp__…` 前缀里就会被静默拒绝。
44. **换会话 / 搬家**（2026-10-22）：不要用控制台的会话重置（会把 socialV2 会话状态整份删掉：聊天缓存、印象、令牌）。手动换：停 bridge → sessions.json 删映射 → social-v2.json 里 bootstrapSent=false → 起 bridge → `POST /api/socialV2/wake` 触发 bootstrap → 新 id 出现后复制 `~/.dsh/fish-memory/<旧>.json` 并在 fish-memory-config.json 打开（插件每 3 秒读配置，不用重启 DSH）。现在她能自己搬（`qq_move_house`，见问题清单 3.16），历史在 `state/session-moves.json`。交接/临时话术用 `state/wake-notes.json`（一次性附言）。会话标题在 `state/session-titles.json`。
43. **抖音策略文件和代码要一起改**：插件运行时每次都重新读 `state/*-policy.json` 并校验范围，先改文件（如分享上限 40）而旧代码还在跑，就会报「许可损坏」直接停掉刷视频。先停、再改文件和代码、再重启。
45. **“管理员”有两个意思**（2026-10-22）：bridge 的安全规则、ownerLabel 里的“管理员”= 主人（ownerQQ）；QQ 群里的管理员是群身份。她在群里的身份由 bridge 按群缓存后写进提示【你在这个群的身份】（`selfGroupRoleTextV2`），查不准时先看 `GET /api/socialV2/group-members?key=group:<群号>` 返回的 `self`。她的群名片和昵称不一样（昵称小鲸鱼，群名片另起），按名字搜不到她自己，要按 QQ 号。
46. **她能禁言/踢人，但只听主人和群主的**（2026-10-22）：`qq_group_manage` → `/api/socialV2/group-manage`，授权全在桥接里硬校验（要求消息的发送者、15 分钟、动作词、点到目标），不靠她自觉；记录在 `state/group-manage.jsonl`。别把校验挪进提示词里。
47. **群友46 5.1 的 `Out-File -Encoding utf8` 会写 BOM**，插件用 `JSON.parse` 读就会失败、静默回落默认值（自动续轮就这样没排上）。写插件/状态 JSON 用 node 或 Write 工具，别用 群友46。

## 主动机会的命中线（2026-10-20 改）
