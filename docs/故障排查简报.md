## 一、这套东西是什么

一个自己搭的 QQ AI 机器人（小鲸鱼），跑在 Windows 上：

|---|---|
| QQ 桥接（主程序，约 13800 行） | `E:\qq-bridge\src\bridge.js` |

| AI 运行时 DSH（Node） | profile `C:\Users\admin\.dsh\profiles\tauri` |
| 抖音浏览器插件 | `C:\Users\admin\.dsh\profiles\tauri\node_modules\dsh-douyin-browser-local\` |

抖音插件控制一个专用 Edge（CDP 端口 `9227`），能刷视频、点赞、评论、分享。

**⚠ 两个坑先记住**
1. **主机时钟快约 3 小时，时区 UTC−8**。日志里的 `HH:mm` 和北京时间差 3 小时且跨日，极易误读。
2. 插件目录下的 `*.mjs` 跑在 **DSH 进程内**，改完必须重启 DSH 才生效（`browser-host.mjs` 只是拉 Edge 的壳，不用动）。

## 二、小鲸鱼报的四个问题

### 问题 1：合并转发读不出来（三个不同 id 全报同一句）

她的原话：
> 调 get_forward_msg，三个不同的转发 id 全都是同一个错「Connection closed」，一次都没成功过

关键线索：报错**没有任何前缀**。正常失败会带「查看合并转发失败：…」，纯 `Connection closed` 说明请求没走到业务层就断了。

**我查到的事实：**

| 检查项 | 结果 |
|---|---|
| `state/bridge.log`（1572 行）里搜「合并转发」 | **一条都没有** → 请求没到 bridge 的 handler，或到了但卡在写日志之前 |
| `state/mcp-snowluma.log`（我新加的崩溃日志） | 只有重启时的 `[exit] code=0`，**进程没崩过** |
| 直连 SnowLuma `GET /get_forward_msg?id=假id` | **385ms 正常返回**：`{"status":"failed","retcode":100,"wording":"download forward message payload is empty"}` |
| 用**假** token 调 MCP 工具 | 返回「查看合并转发失败：未授权：…」→ **链路是通的，工具 catch 正常执行** |

**我的推断（未被证实）**：
真实转发要先"下载转发消息载荷"（几十条消息 + 图片），bridge 里 `await bot.raw('get_forward_msg')` 裸等，这期间 handler 不回包、不写日志（`log()` 写在拿到数据之后）。上游 DSH 的工具调用等不及，先把 MCP 连接关了 → 看到 `Connection closed`。

**我已改的**（`E:\qq-bridge\src\`）：
- `qq-model-view.js`：`compactModelData` 原是**无深度上限、无环检测**的递归。合并转发数据若有环会 `RangeError: 栈溢出`，未捕获异常直接把 MCP 进程带走。已加深度上限 12 层 + WeakSet 环检测（实测：环→null、500 层→截断到 12 层、正常数据不变）。
- `mcp-snowluma-safe.js`：加 `process.on('uncaughtException'/'unhandledRejection'/'exit')` 写 `state/mcp-snowluma.log`。
- `bridge.js`：转发拉取加 **25 秒超时**（`withTimeout`）、入口先 `log('合并转发查询开始 …')`、嵌套预览 10 秒、瞬时断连重试 3 次。

**状态：⚠ 真实转发一次都没成功读到过。** 加了超时和入口日志，但没验证成功。

**想请帮忙的**：如果 25 秒超时仍然拿不到内容，问题到底在哪一层？`retcode:100 download forward message payload is empty` 是否说明 QQ 侧的转发 payload 本身取不到（过期？需要额外权限？）？

### 问题 2：「自主观看必须有同一真实作品的有效采样画面」—— 0 次就挂

**根因（两处叠加，已修好并验证）：**

1. `core.mjs` 的 `capture()` 用 `state.video?.id !== before.id` **严格比较**。抖音 id 会读成 `null` / `undefined` 抖动，`null !== undefined` 成立 → 判定"采样期间切换作品" → 直接 `break`，**一帧都不剩**（`imageStatus` 会写"本次操作没有采集画面"）。
   → 改成 `sameWork()`：只有两边都读出有效 id 且不相等才算真换条。

2. `autonomous-watch.mjs` 第 168 行是**裸调用** `watchDecisionMessages(observation)`，不在任何 try/catch 里。之前的"重采样"补丁只包住了后面的 `decideWatch`，前面这道预检漏了，等于补丁没打。
   → 预检也降级为重采样，连续 5 次才对不上才认输（防死循环）。

**✅ 已验证**：采样 3 帧、时间点前进（3.06→4.65→6.19 秒）、id 一致、`viewing.accepted: true`、`imageStatus`「已向模型提供 3 张画面」。

### 问题 3：「未确认切换到另一条作品，已停止自主观看」

`autonomous-watch.mjs` 的 `skip` 分支：`douyin_next` 之后只要 `changed !== true` 或 id 没变就 `throw failure(...)` 结束整轮。抖音加载慢一拍就判死。

→ 改成最多试 **3 次**（间隔 900ms），三次都没动静才停。**未实测。**

### 问题 4：「当前页面没有唯一可核对的评论输入框」—— needs_user

她当时看的是条生日代码视频（星空蛋糕、9185 条评论）。

**我现场翻了这个页面，发现三件事：**

1. **评论区默认收起**，输入框只有面板展开后才在 DOM 里。
2. **页面里同时有 3 个 `[data-e2e="feed-comment-icon"]`**：`y=-478`（上一条）、`y=699`（当前这条）、`y=1877`（下一条）。Playwright 的 `visible` **只看尺寸和 display，不看元素在不在屏幕内**，所以三个都算"可见"，盲点第一个会点到上一条。
3. **评论框是两段式的**：`.comment-input-container` **在**，但里面**没有 contenteditable / textarea**，只是一个显示「留下你的精彩评论吧」的**假框**。点它一下，真编辑器才出现：`div[contenteditable=true].public-DraftEditor-content`。原选择器直接找 `.comment-input-container [contenteditable="true"]`，因此**永远是 0 个**。

**已改 `comment-browser.mjs`**：先展开评论区（只点视口内的图标）→ 再点假框激活编辑器 → 发布按钮改成「输入后再找」。

**验证结果：**
- ✅ 点击假框后 `editors` 从 0 变 1（`public-DraftEditor-content`）
- ✅ 文字能输进去（`innerText` → `测试abc`，测完立刻 Ctrl+A + Delete 清空，`"\n"`，没留草稿）
- ❌ **发布按钮始终找不到**

**卡住的具体事实：**
- 空输入时全页面（含隐藏元素）没有任何「发送 / 发布 / 发表评论 / 提交」按钮
- 输入文字后**仍然没有**。输入框右侧 `div.GnAJFEwv.commentInput-right-ct` 里只有一个添加图片的按钮（`input[type=file]` + svg 图标）
- 遍历整个可见页面找 `发送|发布|提交|send|submit|post`（文字或 class），只匹配到评论区顶部的 tab「评论」
- 编辑器是 `public-DraftEditor-content`（Draft.js），`page.keyboard.type` 能让 `innerText` 变化

**我的猜测**：可能是 **Enter 提交**，或者需要触发特定的 `beforeinput` / React 受控组件的 state 更新才会渲染发送按钮。**我不敢试 Enter** —— 会真的把评论发出去。

**想请帮忙的**：抖音网页版（douyin.com 推荐流，`?recommend=1`）的评论到底怎么提交？有没有更可靠的定位方式，或者该用 CDP `Input.dispatchKeyEvent` 之类？

## 三、共同模式（我认为这是根子）

上面四个报错，本质是**同一个毛病**：

> 一个瞬时的、环境的失败，直接判掉整轮（failed / needs_user）。

原本设计思路没错（不确定就停下，别做错事），但一次误杀就让整轮陪葬。我正在按下面的标准把它们分开：

- **真需要人介入** → 停：登录、验证、私信面板遮挡、发布结果不确定（可能已发出去）
- **环境抖动** → 跳过 / 重试：采样 id 读不出、翻页没翻动、评论面板没展开、按钮还没渲染

已按此改过的分支：采样、翻页、评论、评论发布判定。
